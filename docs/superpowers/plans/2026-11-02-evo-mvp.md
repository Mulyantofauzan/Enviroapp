# EVO MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Phone-first PWA where operators log weather, pond water in/out and coagulant stock per day, with auto flow, auto stock remaining and out-of-limit highlight.

**Architecture:** npm workspaces monorepo. `packages/shared` holds pure math and types. `apps/api` is Hono on Cloudflare Workers with D1. `apps/web` is a React + Vite PWA that calls the API with a session cookie.

**Tech Stack:** TypeScript, Hono, Cloudflare Workers + D1, Wrangler, Vitest (+ `@cloudflare/vitest-pool-workers` for API), React 18, Vite, `vite-plugin-pwa`, React Router.

**Spec:** `docs/superpowers/specs/2026-11-02-evo-mvp-design.md`

## Global Constraints

- Ids are TEXT UUIDs; dates are TEXT `YYYY-MM-DD`; measurements are REAL.
- Flow stored as m3/s only; m3/d = m3/s * 86400, never saved.
- Coagulant types exactly: `Tawas Serbuk`, `Tawas Batu`, `Kapur`.
- Roles exactly: `Admin`, `Manager`, `Operator`, `Auditor`. Operator and Admin write entries; only Admin manages users, ponds, thresholds.
- Out-of-limit never blocks save. Negative remaining warns but saves.
- Unique keys: weather `(date)`; surface_water `(date, sp_id)`; coagulant `(date, sp_id, type)`. PUT replaces the row.
- Session: HttpOnly cookie. Passwords: PBKDF2 via Web Crypto, per-user salt.
- Errors: JSON `{ error: "plain message" }`.
- Colors: Silt `#E4E8E1`, Peat `#1E2B25`, Moss `#3F6B45`, Pond `#2E6F73`, Alert pink `#F4C7CC`, Overdue red `#B3261E` (unused in MVP).
- Fonts: Bricolage Grotesque (headings), Instrument Sans (body), tabular numerals on number fields.
- Copy: sentence case; button "Save day", toast "Day saved".
- Must work at 360px width; visible focus; respect `prefers-reduced-motion`.
- Plan adds one table not in the spec: `sessions(id, user_id, expires_at)`, needed for the session cookie.

## Review Focus

- Empty, blank or non-numeric number fields: treated as "not entered" (null), not 0; non-numeric text rejected with a plain message.
- Negative or impossible values (negative flow, pH outside 0-14): negative rejected; pH outside 0-14 rejected.
- Invalid or future-garbage dates (`2026-13-45`, `abc`): rejected with 400.
- Deactivated pond: hidden from Today chips, still readable in History, writes rejected.
- Threshold with only min or only max (null side): check ignores the null side.
